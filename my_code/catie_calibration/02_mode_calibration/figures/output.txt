5. MODE ATTRIBUTION -- why soft_argmax cannot be used as a partition
==============================================================================
   Hard argmax (mass toward alt 1) is a deterministic relabelling of c_prev:
   inertia's contribution is phi*c_prev, identically 0 when c_prev=0.

                mean   count
hard_argmax                 
contingent_avg   0.0   69047
exploration      0.0   19312
heuristic        0.0    3393
inertia          1.0  158520

   The Bayesian posterior fixes THAT degeneracy ...
                    mean   count
soft_argmax                     
contingent_avg  0.299388   53439
exploration     0.890327   22567
heuristic       0.779652    7706
inertia         0.698973  166560

   ... but replaces it with a worse one. PROOF: regime r's unnormalised
   responsibility is w_r*P(y|r). For inertia P(alt1|inertia)=c_prev in {0,1},
   so its term is exactly w_I when y==c_prev and exactly 0 otherwise. And
   w_I = (1-tau*H)(1-p_exp)*phi >= 0.71*0.70*0.71 = 0.3529 strictly exceeds
   every other regime's maximum (heuristic <= tau = 0.29; contingent <=
   (1-tau*H)(1-p_exp)*0.29 < w_I; exploration <= (1-tau*H)*0.15 < w_I). The
   inequality holds per-k so it survives the convex k-mixture. Therefore:

       soft_argmax == inertia   <=>   y == c_prev,  identically.

                       mean   count
c_prev soft_argmax                 
0.0    contingent_avg   1.0   37440
       exploration      1.0    2475
       heuristic        1.0    1698
       inertia          0.0   50139
1.0    contingent_avg   0.0   15999
       exploration      0.0   20092
       heuristic        0.0    6008
       inertia          1.0  116421

   every cell mean in {0,1}: True     mismatches: 0 / 250,272
   soft_argmax is the repeat/switch indicator plus a 3-way tiebreak. It
   carries exactly one bit beyond c_prev and that bit IS the outcome, so
   any reliability curve drawn from it is reconstructible from the counts
   above and says nothing about the regimes. No such curve is plotted.

   The gap is monotone in run length and REVERSES SIGN inside both c_prev
   strata. So the headline +0.205/-0.114 split is itself an average over
   oppositely-signed sub-strata -- the same failure mode this chapter is
   about, one level down. CATIE's constant phi under-predicts perseveration
   after long runs and over-predicts it after short ones.
   CONSEQUENCE FOR PHASE 4: an asymmetric inertia (one phi per side of
   c_prev) targets only the main effect and CANNOT represent a within-
   stratum sign reversal. Run-length-dependent or recency-weighted inertia
   is what these data actually demand.

8. TESTING (not asserting) THE E[p] vs E[log p] MECHANISM
==============================================================================
   If the c_prev-conditional miscalibration is what costs CATIE on E[log p],
   then removing it should improve E[log p] while NOT improving (or even
   hurting) E[p]. Recalibrating in three ways:

   forecast                               E[p]   E[log p]      ECE
   CATIE as-is                          0.6339    -0.6551   0.1540
   c_prev stratum rate                  0.5712    -0.6191   0.0000
   c_prev x streak_bin rate             0.6175    -0.5631   0.0000
   isotonic on p_alt1 (in-sample)       0.6118    -0.5695   0.0000

   The dissociation is real: correcting the c_prev-conditional gap
   IMPROVES E[log p] while LOWERING E[p] -- exactly the trade the
   E[p]/E[log p] disagreement consists of.
   CAVEAT: the isotonic row is IN-SAMPLE and so is an optimistic bound,
   not a held-out result. And a full causal claim about why CATIE loses
   to Q-Learning needs QL's own conditional calibration profile, which is
   NOT computed anywhere in this repo. Stated as a mechanism consistent
   with the data, not as a demonstrated cause.
